# moon_shadow_example

A module that reads **its own** `moon.mod` at runtime through `moon_shadow`.

```moonbit nocheck
let info = @moon_shadow.current()
println(info.name)    // "nrzhangsan/moon_shadow_example"
println(info.version) // "0.2.0"
```

Run it from this directory:

```
moon run --target js cmd/main
```

## How the metadata gets in

`moon_shadow` reads metadata through the virtual package
`nrzhangsan/moon_shadow/shadow`. This module implements it in `shadow_impl/`
and points `overrides` at that package:

```moonbit nocheck
options(
  overrides: [ "nrzhangsan/moon_shadow_example/shadow_impl" ],
)
```

`shadow_impl/generated.mbt` is committed, so a clean clone needs no extra step.
It is regenerated by the `gen` rule in the library's `shadow/moon.pkg`, and CI
fails when it drifts from `moon.mod`.

`moon.work` lives here rather than in the repository root: the library builds
fine on its own, and only this example needs the two modules side by side to
compile an override against the virtual package.
